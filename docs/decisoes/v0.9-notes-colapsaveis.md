Sem hierarquia visual, sem separação entre seções, informação "jogada".

## Decisão

**Notes viraram CARDS COLAPSÁVEIS**, fechados por padrão.

**Razões**:
1. **O painel é "índice"** — você abre pra achar algo, não pra ler tudo
2. **Cards abertos por padrão = tela sempre cheia** (problema de "jogado")
3. **Resumo de 1 linha** já dá o contexto do que a note tem
4. **Click pra abrir** = intencionalidade (você SABE que quer ler aquela note)
5. **Toolbars "Expandir/Colapsar todas"** = escape valve pra quem quer ver tudo

## Design

### Estrutura do card

**Fechado** (padrão):
```
┌──────────────────────────────────────────────────────┐
│ ▸  Time                Quem faz o quê no Instituto...  NOTA │
└──────────────────────────────────────────────────────┘
```

**Expandido** (após click):
```
┌──────────────────────────────────────────────────────┐
│ ▾  Time                Quem faz o quê no Instituto...  NOTA │
├──────────────────────────────────────────────────────┤
│                                                       │
│   Quem faz o quê no Instituto Kronos.                │
│                                                       │
│   JU (JULIANA MAGALHÃES)        ← h4 mono bold       │
│   - Papel: Expert / Estratégia ← lista com ▫         │
│   - Aulas, oficinas ao vivo, ...                      │
│                                                       │
│   PRÓXIMOS PASSOS                ← h4 mono bold       │
│   - [ ] Revisar se o time cobre tudo                │
│                                                       │
└──────────────────────────────────────────────────────┘
```

### Componentes

- `.note-card` — container com border + border-radius
- `.note-card-header` — header clicável (44px min-height)
- `.note-card-chevron` — ▸ (cinza) / ▾ (rosa) com rotação 90° animada
- `.note-card-title` — bold 13.5px
- `.note-card-summary` — resumo 1 linha (1ª linha útil do conteúdo, com data/autor removidos)
- `.note-card-badge` — "NOTA" em mono uppercase
- `.note-card-actions` — ✎ ↗ 🗑 (opacity 0 → 1 no hover)
- `.note-card-body` — conteúdo (escondido por default, visível quando `.expanded`)

### Hierarquia interna da note

| Elemento | Estilo |
|---|---|
| `h3` (section title) | mono 11px, letter-spacing 0.12em, uppercase, dim |
| `h4` (subsection) | mono 10.5px, letter-spacing 0.1em, uppercase, dim |
| `<p>` | line-height 1.7, font-size 14px |
| `<ul>` | sem bullet, `▫` rosa-faint antes de cada item |
| `<hr>` (entre seções) | border-top 1px (se tiver) |

## Toolbar (quando 2+ notes no escopo)

Aparece antes do grupo de notas:
```
// N notas  [Expandir todas]  [Colapsar todas]
```

- Estado persiste por noteId no `currentView.expandedNotes` (Set<string>)
- Click individual na chevron/header toggle só aquela note
- Click no "Expandir todas" expande todas do escopo

## Revertendo decisão v0.4-v0.7

A v0.4 introduziu "notas como ARTIGO" (sem wrapper, texto fluindo). v0.5 removeu o wrapper. v0.7 expandiu tudo por padrão.

**v0.9** é uma reversão consciente: notas VOLTARAM a ter wrapper (o card), mas o wrapper é o **controle** de colapso, não o conteúdo (conteúdo ainda flui como artigo dentro do card expandido).

## Aprendizado

> **"Artigo aberto" não funciona pra índice.** Quando o painel é "índice de tudo", o usuário precisa de **cards colapsáveis** com resumo de 1 linha. Notas longas ainda são lidas, mas sob demanda. Mesmo o Notion, que é block-based, usa cards/tiles pra overview e só expande no click.
