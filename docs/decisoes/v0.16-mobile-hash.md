## Contexto

Marcelo reclamou: "O acesso ao mobile ainda não está bom, sobretudo a barra de cima, a opção de voltar, etc."

Mavis tirou prints via puppeteer (iPhone 14 Pro, 393x852) e identificou 4 problemas:
1. Top nav SEM os links principais (Gestão, Operação, etc) — sumiram no mobile
2. Sem botão "voltar" quando entrava em Comercial/Marketing/etc
3. Busca (⌕) escondida no mobile
4. Botão TOC ≡ muito grande, sobreposto nos cards

## Decisão

Implementar 4 features:
1. **Nav-burger** (☰) + drawer lateral
2. **Breadcrumb "← Voltar"** em sub-escopos
3. **Hash routing** — URL muda conforme navega
4. **CSS @media** responsivo

## Como foi implementado

### Nav-burger + drawer (mobile)
```html
<button class="nav-burger" onclick="openNavDrawer()" aria-label="Menu">☰</button>

<div class="nav-drawer" id="nav-drawer">
  <div class="nav-drawer-bg" onclick="closeNavDrawer()"></div>
  <div class="nav-drawer-panel">
    <div class="nav-drawer-head">
      <h3>// Menu</h3>
      <button class="nav-drawer-close" onclick="closeNavDrawer()">✕</button>
    </div>
    <ul class="nav-drawer-list" id="nav-drawer-list"></ul>
  </div>
</div>
```

```css
.nav-burger { display: none; ... }
@media (max-width: 1100px) {
  .nav-burger { display: flex !important; }
  .nav-drawer { display: block !important; }
  .navlinks { display: none; }
}
```

### Breadcrumb "← Voltar"
```js
if (currentSubScope) {
  const subName = ESTRUTURA[currentView].areas[currentSubScope]?.titulo || ...;
  html += `<div class="breadcrumb">
    <a href="#" onclick="event.preventDefault();navigate('${currentView}')">← ${esc.titulo}</a>

  </div>`;
}
```

```css
.breadcrumb { display: none; ... }
body[data-sub] .breadcrumb { display: flex; }
```

### Hash routing
```js
function navigate(scopeKey, subKey) {
  // ...
  const newHash = scopeKey === 'home' ? '#/' : '#/' + scopeKey + (currentSubScope ? '/' + currentSubScope : '');
  if (location.hash !== newHash) {
    history.replaceState(null, '', newHash);
  }
  // ...
}

function parseHashAndNavigate() {
  const h = location.hash.replace(/^#\/?/, '');
  if (!h) { if (currentView !== 'home') navigate('home'); return; }
  const parts = h.split('/').filter(Boolean);
  const scope = parts[0];
  const sub = parts[1];
  const validScopes = ['gestao','operacao','produtos','sops','biblioteca','conhecimento'];
  if (!validScopes.includes(scope)) { if (currentView !== 'home') navigate('home'); return; }
  navigate(scope, sub);
}
window.addEventListener('hashchange', parseHashAndNavigate);

// no boot:
if (location.hash && location.hash !== '#/' && location.hash !== '#') {
  parseHashAndNavigate();
} else {
  renderHome();
}
```

### `data-view` e `data-sub` no body
```js
document.body.dataset.view = scopeKey;
document.body.dataset.sub = currentSubScope || '';
```

Permite CSS condicional: `body[data-sub] .breadcrumb { display: flex; }`

## Bug encontrado durante implementação

**CSS @media não aplicava** mesmo com `@media (max-width: 1100px)`.

Causa: ordem no arquivo. Os defaults (`.nav-burger{display:none}`) vinham **DEPOIS** do `@media`, sobrescrevendo-o.

**Fix**: adicionar `!important`:
```css
@media (max-width: 1100px) {
  .nav-burger { display: flex !important; }
  .nav-drawer { display: block !important; }
}
```

## Lições

- **Mobile é obrigatório** mesmo pra apps "desktop-first" — Marcelo usa no celular
- **CSS source order** importa: defaults devem vir ANTES de @media queries (ou usar !important)
- **Hash routing** é mais simples que path routing (não precisa configurar rewrites na Vercel)
- **Breadcrumb "← Voltar"** é UX básica mas essencial no mobile (sem histórico de tab visual como no desktop)
